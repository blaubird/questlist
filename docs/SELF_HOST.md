# Самохост: GitHub Pages + PocketBase на домашнем компе + Tailscale Funnel

Бесплатно и без домена. Интерфейс всегда доступен, сервер сохранений работает, пока включён комп.

## Схема

```
GitHub (публичный репо) ──push main──► GitHub Actions ──build──► GitHub Pages
                                                                     https://<ник>.github.io/questlist   ← интерфейс (PWA)

Телефон / комп ── HTTPS ──► Tailscale Funnel ──► localhost:8090 PocketBase (только /api)
                            https://<комп>.<tailnet>.ts.net/api                       ← вход и сохранения
```

- **Офлайн-first:** сохранение всегда сначала пишется локально (IndexedDB). Если комп выключен или спит, приложение работает как обычно, а синхронизация ждёт, пока сервер снова появится. Синхронизируется журнал событий: каждое устройство отправляет свои события и забирает чужие, слияние по id события (см. `GAME_SPEC.md` → «Сохранение»).
- **Секретов в репозитории нет.** Адрес API — публичная константа сборки `VITE_API_URL`. Пароли хранятся только в PocketBase и в менеджере паролей владельца.

## Компоненты на компе

- **PocketBase:** один бинарник, версию зафиксировать. Папка `~/questlist-server/` (на Windows — `%USERPROFILE%\questlist-server\`), данные в `pb_data/`, миграции копируются из `deploy/pb_migrations/` репозитория.
- **Автозапуск (Windows, этот комп):** `deploy/install-server.ps1` от администратора. Задача Планировщика «Questlist PocketBase» — **при запуске системы**, от SYSTEM, перезапуск при падении. Скрипт копирует миграции и хуки из репо в `%USERPROFILE%\questlist-server\`; повторный запуск = обновление сервера. PocketBase слушает только `127.0.0.1:8090` (dev-сервер `pnpm pb` — на 8091).
- **Tailscale:** приложение установлено и вошло в аккаунт владельца. Funnel публикует **только путь `/api`**, админка `/_/` снаружи недоступна:
  `tailscale funnel --bg --set-path=/api http://127.0.0.1:8090/api`
  (Перед первым запуском Funnel нужно один раз разрешить в админке Tailscale: включить HTTPS-сертификаты и атрибут funnel. CLI сам даёт ссылку.)
- **CORS:** флаг `--origins=https://<ник>.github.io`.
- **Защита служебных API:** вход суперпользователя и служебные эндпоинты тоже живут под `/api`. Хук `deploy/pb_hooks/guard.pb.js` отвечает 403 на них для любого запроса, пришедшего через прокси (есть `X-Forwarded-For` и т. п.). Локально админка работает. Включены лимиты частоты запросов.

## PocketBase

- Коллекция `events`: `user`, `eid` (уникален в паре с user), `ts`, `dev`, `type`, `data`, `created`. Правила list/view/create — только свои; update и delete запрещены (журнал неизменяемый).
- Коллекция `snapshots`: `user` (unique), `upto`, `t`, `data`. list/view/create/update — только свой; delete запрещён.
- Вход: email + пароль, токен живёт 90 дней и продлевается при каждой синхронизации. Регистрация закрыта миграцией с самого начала; аккаунт игрока владелец создаёт сам в админке (коллекция users).
- Новые миграции применяются при запуске PocketBase: после обновления схемы перезапустить `deploy/install-server.ps1` от администратора.
- Первого суперпользователя создаёт **владелец сам в браузере**: при первом запуске PocketBase печатает одноразовую ссылку установки (`http://127.0.0.1:8090/_/#/pbinstal/...`). Claude только показывает её. Пароль в консоль и историю команд не попадает.
- Миграции схемы — JS-миграции в `deploy/pb_migrations/`. Схема живёт в репозитории.

## GitHub Actions

- На PR и push: `pnpm i --frozen-lockfile && pnpm typecheck && pnpm test && pnpm build`.
- На push в `main`: сборка с `base: '/questlist/'` и деплой через `actions/deploy-pages`. Pages включается через `gh api` (source: GitHub Actions).
- Переменная `VITE_API_URL` хранится в Repository Variables (это не секрет).

## Бэкапы

- PocketBase сам делает бэкап каждые 6 часов в `pb_data/backups` (настроено миграцией, хранит 8).
- Задача «Questlist Backup» (ежедневно в 04:00 и при входе) запускает `backup.ps1`: копирует новые архивы в `OneDrive\questlist-backups`, хранит 14. Пароль администратора скрипту не нужен. Лог — `questlist-serverackup.log`.
- Плюс в приложении всегда есть ручной экспорт сохранения в JSON.
- Раз в месяц проверять восстановление: поднять PocketBase из бэкапа во временной папке.

## Проверка, что всё работает (этап 0)

1. `https://<ник>.github.io/questlist/` открывается с телефона по мобильной сети (Wi-Fi выключен).
2. `https://<комп>.<tailnet>.ts.net/api/health` с телефона по мобильной сети отвечает `200`.
3. `https://<комп>.<tailnet>.ts.net/_/` снаружи **не** открывается.
4. После перезагрузки компа PocketBase и Funnel поднимаются сами.
4а. `POST https://<комп>.<tailnet>.ts.net/api/collections/_superusers/auth-with-password` снаружи отвечает `403`.
5. Push в `main` за несколько минут появляется на Pages без ручных шагов.

## Если позже понадобится сервер 24/7

Тот же PocketBase и те же миграции переносятся на VPS (Hetzner и подобные, около 4–5 € в месяц) без изменений в коде. Меняется только `VITE_API_URL`.
